# 02k 逆向对抗矩阵（破坏者立场的系统化清单）

> 逆向用例从的工作骨架（B7）。每行=一个破坏维度对目标输入的攻击；配合 BUG 模式库滚动扩充。

## 目标模块：<模块名>

| 破坏维度 | 攻击输入/操作 | 预期（正确行为） | 恢复条件 | 复现计数 | 关联BUG |
|----------|----------------|------------------|----------|----------|---------|
| 空值/缺省 | 必填项留空提交 | 前端拦截或后端 4xx，不落库 | - | N/M | |
| 超长/边界 | 输入 10KB 文本/整数边界正负1 | 截断或校验拒绝，不崩溃 | - | N/M | |
| 断网/弱网 | 提交瞬间断网（Toxiproxy） | 超时提示+可重试，不重复提交 | 网络恢复后状态一致 | N/M | |
| 并发冲突 | 双端同时操作同一资源 | 后端一致性保障（锁/版本），一方可感知失败 | - | N/M | |
| 权限缺失 | 无权限 token 访问受保护接口 | 403，不泄漏数据 | - | N/M | |
| 状态跳跃 | 跳过前置步骤直达后置操作（深链/改本地状态） | 拒绝或引导回前置，不死循环 | - | N/M | |
| 降级/回退 | 操作中途取消/返回/杀进程 | 状态回滚到一致点，无半成品残留 | - | N/M | |
| （按模式库滚动新增行） | | | | | |

## 使用规则
- 每轮逆向用例从按本矩阵逐维度过一遍，模式库新增模式必须加对应行
- 恢复条件列是硬要求：破坏后系统必须能回到可用状态（破坏性测试的收尾纪律）
- 复现计数真实记录（N/M），禁写"偶现"
