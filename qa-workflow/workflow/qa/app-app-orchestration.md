# [TARGET_APP] 多会话调度工作流

## 目标与边界

本文件定义 [TARGET_APP] 本地开发、运行与测试的统一调度机制。`[TARGET_APP]｜全局运维与测试统筹` 是唯一的主会话：接收用户目标、维护全局环境与版本矩阵、拆解任务、调度专项会话、复核回报并决定下一轮工作。

QA 专项编排采用 `codex-qa-orchestration.md`；任务卡模板为 `templates/qa-task-card.yaml`。该适配层吸收 AIQA-MiaoYu 的双环、L1-L4 分级、正向/逆向对抗和证据链规则，但不改变本文件的主会话审批边界。

专项会话只在自己的项目边界内执行，不直接改变其他项目、共享工具链、测试服务器或生产资源。工程执行标准以 `workflow-codex-agents.md` 的六环节流水线为准；本文件只补充多会话协作协议。

## 会话职责

| 会话 | 负责范围 | 不负责范围 |
| --- | --- | --- |
| 主会话 | Git/SSH、全局工具链、磁盘与目录、版本矩阵、测试配置、数据库隔离、API 契约、任务调度和结果复核 | 在未派发前由专项会话承担的项目内细节 |
| 移动原生测试 | Android、iOS 的构建、安装、权限、真机能力和原生回归 | Flutter Core、服务端、全局环境变更 |
| Flutter 跨端测试 | FlutterApp、Flutter Core、FlutterModule 的依赖、构建、嵌入和跨端回归 | 服务端数据迁移、全局环境变更 |
| 服务端与 AI 测试 | Server、Server-AI、接口、管理端、数据库本地镜像与 AI mock | 客户端构建、共享工具链变更 |

## 统一基线

每次联调必须使用主会话登记并下发的版本矩阵、环境标识、API 契约版本和测试数据版本。当前候选开发基线为：

```text
Android:                 [COMPANY] Network-Android/dev
Flutter:                 [COMPANY] Network-FlutterApp/dev
Flutter Core:            [company-]network_flutter_core/dev
Flutter Module:          [COMPANY] Network-FlutterModule/dev
iOS:                     [COMPANY] Network-iOS/dev
iOS Framework:           [COMPANY] Network-iOS-Framework/dev
Server / Server AI:      先比较 main 与 master 后由主会话冻结联调基线
```

未经主会话确认，不将不同分支、不同 API 版本或不同测试数据混合为同一次联调结论。

## 调度循环

1. **主会话建卡**：为任务指定目标、受影响项目、基线、验收条件、依赖、风险等级和是否允许写入。
2. **专项会话执行**：只执行任务卡范围，遵循需求与边界、方案、执行、审查、验证六环节；未获授权不得拉取、安装、改配置或连接外部资源。
3. **结构化回报**：专项会话回传状态、实际基线、改动/命令、验证证据、产物位置、阻塞项、风险与下一步建议。
4. **主会话复核**：检查基线一致性、证据完整性和跨项目影响；必要时向其他专项会话派发依赖任务或交叉验证。
5. **闭环决策**：主会话将结果标记为完成、返工、阻塞或等待用户决策，并将下一轮任务分发给对应会话。

## 任务卡格式

```text
任务 ID：<主会话生成>
目标：<可验证的业务或运行目标>
范围：<仓库/模块/文件或环境>
基线：<分支 + commit，或待主会话冻结>
输入与依赖：<配置、服务、设备、上游任务>
允许操作：<只读/拉取/安装/本地写入/受控测试环境>
验收：<命令、测试、截图、日志或接口证据>
禁止项：<生产资源、提交、推送、全局配置等>
回报格式：状态；证据；阻塞；风险；建议下一步
```

## 并发与写入规则

- 同一时刻最多并发运行三个专项会话；主会话保留一个槽位用于协调和复核。
- 不同会话使用独立检出目录、构建缓存、端口、数据库名和 `.env` 文件。
- 多会话可以并发做只读审阅、环境核验、独立构建与测试；同一仓库、同一配置、同一数据库迁移只能由一个会话持有写入权。
- 专项会话不得自行新建分支、提交、推送、创建合并请求、安装全局工具或连接生产资源。
- 影响 API、数据库 schema、共享 Flutter Core、构建工具链或测试数据的变更必须先回主会话复核后再派发。

## 本地环境与数据隔离

- 代码、构建缓存、测试产物和数据库数据使用 E 盘的独立根目录，避免消耗 C 盘空间。
- 本地数据库优先使用版本化 schema + 脱敏快照或最小种子数据；先完成本地健康检查，再批准受控测试服务器联通。
- 测试服务器只能使用独立测试账号和命名空间；默认最小权限，生产资源永不作为本地联调依赖。
- 密钥、账号、证书和 AI 配额不进入仓库、任务回报或共享文档；由主会话按需、最小范围下发。

路径、文档、工具与数据分层以 `local-storage-governance.md` 为准：E 盘管理代码与可重建运行资产，F 盘管理工具链和长期过程/结果文档，G 盘管理分级数据与数据库快照。任务卡必须注明根目录、结果目录和数据标签。

## 统一完成定义

一个任务只有在以下信息齐备时才可由主会话标为完成：实际执行基线、可复查的验证证据、产物或日志位置、已知限制、跨项目影响结论。没有证据的结果只能标记为“待验证”，不能标记为完成。
