# Codex QA 工作流适配设计

## 目标

把 AIQA-MiaoYu 的测试方法论接入 [TARGET_APP] 现有 Codex 主会话治理。第一阶段只建立协议、任务卡和自检，不拉取新项目、不连接生产、不改模型或网关配置。

## 组件与边界

| 组件 | 责任 | 不负责 |
|---|---|---|
| 主会话 | 接收目标、冻结基线、拆任务、合并双通道结果、复核证据、决定外部动作 | 代替专项任务深入执行全部项目细节 |
| 考古任务 | 逆向代码、维护系统认知和接口清单 | 设计用例、执行测试、提 BUG |
| 正向用例任务 | 从主路径和数据流生成 L1-L4 正向用例 | 破坏性输入、执行测试 |
| 逆向用例任务 | 从已知坑和 BUG 模式生成边界、非法、并发、断网等用例 | 读取正向任务中间状态、执行测试 |
| 执行任务 | 运行 API/UI/设备/性能/安全测试并采集证据 | 定级、提单、修改共享配置 |
| 报告任务 | 依据执行证据生成轮次报告、BUG 草稿和周期汇报 | 未经主会话复核向外发送 |

## 数据流

1. 主会话创建任务卡并冻结项目分支、commit、测试数据标签和结果目录。
2. 考古任务先写系统认知；正向和逆向任务并行产出互不可见的用例文件。
3. 主会话合并去重并记录覆盖缺口，再派执行任务。
4. 执行任务将命令、日志、截图、录屏和报告写入 F 盘结果目录；临时运行数据写入 G 盘测试区。
5. 报告任务只引用证据路径生成 BUG 草稿；主会话复核后才允许缺陷管理系统等外部写入。
6. 轮次结果回写知识库索引和 BUG 模式，作为下一轮输入。

## 并发与写入策略

- 同一仓库、同一数据库、同一共享配置只允许一个写入持有者。
- 正向/逆向任务可并行，但写入独立文件；`00-索引.md`、接口清单和模式库由主会话顺序合并。
- 每个结果目录必须包含 `summary.md`、`commands.txt`、`evidence/` 和 `risks.md`；不存在的证据必须明确标记未执行。

## 路径与数据规则

- 代码与可重建脚本：`E:\[TARGET_APP]`。
- 工具、长期文档、清单和结果：`F:\[TARGET_APP]-Toolchain`。
- 临时数据、测试数据库、脱敏快照和原始日志：`G:\[TARGET_APP]-Data`。
- 任务 ID 格式：`SWAN-YYYYMMDD-序号-主题`。
- `production-controlled` 数据必须经过主会话审批，不能被默认本地服务加载。

## 失败与状态

- `BLOCKED`：缺设备、账号、服务或权限，必须记录阻塞证据和恢复条件。
- `待验证`：有结论但缺完整证据，禁止进入完成状态。
- `返工`：主会话发现基线、步骤、证据或定级不合格，原任务卡保留并创建修订记录。
- `完成`：实际 commit、命令输出、产物路径、限制和跨项目影响均已复核。

## Codex 适配原则

- AIQA-MiaoYu 中 Claude Code 的 `.claude/agents` 仅作为职责参考，不直接安装或复制。
- 不复制其中的模型、网关、API 密钥、`bypassPermissions` 或全局权限设置。
- Git MCP、Playwright、Maestro、pytest 和安全扫描作为现有工具按任务卡声明使用。
