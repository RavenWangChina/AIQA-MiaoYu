# [TARGET_APP] Codex QA 统一编排协议

## 适用范围

本协议将 AIQA-MiaoYu 的 QA 方法论接入 [TARGET_APP] 主会话。主会话是唯一调度入口；专项任务只在任务卡声明的仓库、模块、环境和数据标签内工作。

## 双环模型

- **测试环**：接单 → 模块分析 → 正向/逆向用例 → 执行 → 证据采集 → 报告 → 回归。
- **知识环**：系统认知、接口清单、用例、BUG 模式和报告持续写入文档，并反哺下一轮任务。
- **测试级别**：L1 冒烟、L2 功能、L3 场景、L4 探索；每张任务卡必须声明覆盖级别。

## Codex 专项任务角色

### 考古任务

读取指定仓库和模块，产出架构、入口、依赖、接口、数据流和已知坑。不得设计用例、执行测试或提 BUG。

### 正向用例任务

从模块卡片的主路径和数据流设计“功能做了该做的”用例。不得设计破坏性输入，不读取逆向任务的中间文件。

### 逆向用例任务

从已知坑和 BUG 模式覆盖边界、非法输入、超长/空值、并发、中断、断网、权限缺失和状态跳跃。不得读取正向任务的中间文件。

### 执行任务

按任务卡运行 pytest/httpx、Playwright、Maestro、adb、go-ios、k6、Schemathesis、ZAP 等已声明工具，自动采集环境并保存日志、截图、录屏和报告。无法执行时必须标记 `BLOCKED`。

### 报告任务

只使用执行证据生成轮次报告、BUG 草稿和周期汇报；复现概率使用真实计数，环境来自自动采集。未经主会话复核不得向缺陷管理系统或其他外部系统写入。

## 主会话编排步骤

1. 读取 `00-索引.md` 和任务卡，确认基线、范围、数据标签和允许操作。
2. 无模块卡片时先派考古任务。
3. 并行派正向与逆向任务，分别写独立文件。
4. 主会话合并去重，记录覆盖缺口和分歧；同一知识索引只由主会话顺序更新。
5. 派执行任务，声明 L1-L4 层级和双通道矩阵行。
6. 派报告任务生成轮次报告和 BUG 草稿。
7. 主会话复核步骤、证据和定级；只有复核通过才执行外部提单。
8. 回写知识库索引、BUG 模式和任务结果，形成下一轮输入。

## 统一回报格式

每个专项任务必须返回：`status`、`actual_baseline`、`commands`、`evidence_paths`、`blockers`、`risks`、`next_step`。完整产物写入任务卡指定的结果目录，只向主会话回传摘要和路径。

## 状态和审批

- 没有命令输出、截图、日志或接口响应等证据时，状态不得标记为完成。
- `BLOCKED` 需要写明缺失资源和恢复条件；`待验证` 需要写明补证据动作。
- 提交、推送、合并请求、缺陷管理系统提单、权限变更、数据库迁移、生产访问和删除/覆盖重要数据均由主会话另行取得用户确认。

## 路径与安全

- 代码和可重建脚本使用 `E:\[TARGET_APP]`。
- 工具、过程文档、清单和长期结果使用 `F:\[TARGET_APP]-Toolchain`。
- 临时数据、测试数据库、脱敏快照和日志使用 `G:\[TARGET_APP]-Data`。
- 不复制 Claude 专用的模型、网关、API 密钥、`bypassPermissions` 或全局权限设置。
